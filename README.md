## BlindNav: Edge AI Navigation System
---
BlindNav — это программно-аппаратный комплекс автономной навигации для людей с нарушениями зрения. Система работает полностью Offline (Edge AI), объединяя компьютерное зрение на NPU, спутниковую навигацию и нейросетевой синтез речи в едином носимом устройстве.

Разработано в рамках выпускной квалификационной работы (ВКР) в Санкт-Петербургском государственном университете аэрокосмического приборостроения (ГУАП).

### Основные возможности

1. Hardware-Accelerated Vision: Инференс модели YOLOv11-Nano (INT8) на NPU Rockchip RK3566 — 25 FPS на потоке кадров, ~18 FPS сквозного конвейера с камерой. Замеры скорости и точности — в [METRICS.md](METRICS.md).

2. Семантический анализ среды: Распознавание 10 классов городских объектов (люди, транспорт, инфраструктура) с расчетом дистанции и приоритезацией опасности.

3. Локальный Neural TTS: Мгновенное оповещение через нейросетевой движок Piper (ONNX).

4. Offline Геопозиционирование: Маршрутизация на базе OSRM и локальных OSM-графов без доступа к интернету.

5. Headless-ready: Автоматизация запуска всего комплекса через systemd.

### Техническая реализация

| Компонент | Технологии |
| :--- | :--- |
| **CV Core** | C++17, RKNN API, OpenCV |
| **AI Model** | YOLOv11-Nano (квантованная) |
| **Routing** | OSRM (в Docker), OpenStreetMap (`.pbf`) |
| **TTS/STT** | Piper (ONNX), Vosk |
| **Deployment** | Docker (только OSRM), systemd (остальные сервисы) |

### Быстрый старт (Orange Pi, чистая плата)

```bash
git clone <repo> /root/diplom-cpp && cd /root/diplom-cpp

# 1. Системные сервисы (systemd-юниты + автозапуск)
sudo bash deploy/install.sh

# 2. Сборка C++ ядра
cd blind_nav && mkdir -p build && cd build
cmake .. && make -j4
cd ../..

# 3. OSRM (Docker) — граф уже в git, ничего собирать не нужно
sudo systemctl start osrm.service

# 4. Остальные сервисы
sudo systemctl start bt_keeper.service nav_daemon.service blind_nav_main.service
```

### Голос

Все фразы устройство произносит через один скрипт — `tools/say.sh`, — который
зовут и C++ ядро, и python-демон. Синтез piper на этой плате стоит около
5.5 секунды на короткую фразу (из них ~3.5 — загрузка модели при каждом
запуске), поэтому фразы с заранее известным текстом синтезируются один раз:

```bash
bash tools/build_voice_cache.sh
```

Сборка разовая и небыстрая — порядка получаса на 440 фраз, лучше при
остановленном `blind_nav_main`. Кэш кладётся в `piper/cache/` (около 40 МБ) и
покрывает все предупреждения об опасности
(класс x сторона x целые метры) и все подсказки поворотов — из кэша фраза
начинает звучать за десятки миллисекунд вместо пяти с половиной секунд.
Списки берутся из боевого кода (`blind_nav/tools/voice_phrases.cpp` и
`python/phrases.py`), а не выписываются в скрипте, поэтому кэш не может
разойтись с тем, что устройство произносит на самом деле. Промах кэша не
ошибка: фраза синтезируется на месте и тут же в кэш и попадает.

Параметры синтеза и пути звукового тракта заданы в `tools/voice_env.sh` —
единственном месте; там же записан MAC гарнитуры.

### Запись прогулки

Запись включается сама вместе с устройством и не требует никаких действий:
`blind_nav_main.service` пишет кадры с рамками, `nav_record.service` — звук,
он же собирает готовый ролик. Всё складывается в `videos/`.

По достижении 500 МБ текущий файл закрывается и начинается следующий; отрезки
одного дня различаются номером в конце тега (`19_08_2026`, `19_08_2026_2`, …).
Если на разделе остаётся меньше 2 ГБ, запись видео приостанавливается — забитая
под ноль карта означает не «нет ролика», а неработающее устройство. Как только
место появилось (монтаж удаляет исходные MJPG), запись возобновляется сама.

Что получается на каждый отрезок:

| Файл | Что внутри |
| --- | --- |
| `full_video_ДД_ММ_ГГГГ.mp4` | итог: картинка с рамками + голос модели + голос человека |
| `raw_video_ДД_ММ_ГГГГ.mp4` | та же картинка без звука |
| `piper_sound_ДД_ММ_ГГГГ.mp3` | только голос модели, на шкале времени видео |
| `micro_sound_ДД_ММ_ГГГГ.mp3` | только голос человека: диктовка с гарнитуры и уличный фон |
| `ambient_ДД_ММ_ГГГГ.mp3` | исходная непрерывная запись фонового микрофона |
| `session_ДД_ММ_ГГГГ.meta` | начало записи, число кадров и реальный FPS |
| `speech_ДД_ММ_ГГГГ/` | отдельные реплики с метками времени |

Монтаж запускается сам через полминуты после того, как запись прекратилась
(ядро остановлено), и ещё раз через минуту после загрузки платы — так
подхватываются прогулки, оборванные снятием питания. Вручную:

```bash
bash tools/montage_session.sh --all        # смонтировать всё несмонтированное
KEEP_CAPTURE=1 bash tools/montage_session.sh 19_08_2026   # с сохранением исходного MJPG
```

Кодирование тяжёлое, поэтому идёт с `nice 19` и в два потока: ядра нужны
распознаванию препятствий. Отрезок, который пишется прямо сейчас, монтаж не
трогает. Единственный случай, когда кодирование может совпасть с прогулкой, —
догоняющий монтаж после перезагрузки; отключается через
`MONTAGE_ON_START=0` в `nav_record.service`.

Перед съёмкой стоит убедиться, что микрофоны действительно пишут — тишина в
записи выглядит так же, как рабочий микрофон в тихой комнате:

```bash
bash tools/mic_check.sh
```

Подробности и чек-лист ручной проверки — в [TESTING.md](TESTING.md); сборка
и пересборка графа OSRM — в [deploy/osrm/README.md](deploy/osrm/README.md).
