# Сборка датасета для дообучения

Инструменты для пополнения обучающей выборки из открытых источников и из
собственных записей устройства. Причины, по которым это вообще нужно, —
в [METRICS.md](../../METRICS.md): модель недообучена, половина разметки
мельче 16 px при входе 512, а снят датасет с капота машины, тогда как
устройство смотрит с груди пешехода.

## Что уже использовано

Текущий `E:\DATASET` собран **из Mapillary Vistas**: имена файлов — это
22-символьные идентификаторы изображений Mapillary (`--SWG8TJo7vrbZ_x5YLj6A.jpg`),
и набор классов (`curb`, `sidewalk`, `crosswalk`, `pole`, `trash_can`, `bench`)
повторяет классы Vistas. То есть источник, который в таблице ниже
единственный закрывает `curb`, уже выбран почти целиком:

| | файлов | из них оригиналов Mapillary |
| :--- | ---: | ---: |
| `images/train` | 33457 | **13921** |
| `images/val` | 1997 | 1997 |
| `archive/images` | 8347 | 5387 |

Отсюда два вывода, которые меняют план:

1. **58% обучающей выборки — это офлайн-копии** (`_aug_0`, `_aug_1`) тех же
   13921 картинок. Реального материала втрое меньше, чем кажется по числу
   файлов, и «мало данных» здесь означает 14 тысяч, а не 33.
2. **Vistas почти исчерпан.** Уникальных изображений в train+val 17035 при
   примерно 20 тысячах размеченных во всём датасете. Докачивать его ради
   `curb` смысла почти нет — потолок около +3 тысяч кадров.

Утечки между train и val нет: пересечение по идентификаторам пустое,
аугментированные копии train в val не попали.

## Что можно взять готовым, а что нет

Проверено по официальному списку классов Open Images V7; для источников
с регистрацией состав классов взят из их описаний.

| Наш класс | Open Images V7 | COCO 2017 | Mapillary Vistas | SideGuide |
| :--- | :--- | :--- | :--- | :--- |
| `person` | `Person` | `person` | есть | есть |
| `car` | `Car`, `Van`, `Truck`, `Bus` | `car`, `truck`, `bus` | есть | есть |
| `curb` | **нет** | **нет** | `Curb`, `Curb Cut` | есть |
| `pole` | `Street light` (частично) | **нет** | `Pole`, `Street Light` | есть |
| `traffic_sign` | `Traffic sign`, `Stop sign` | `stop sign` | есть | есть |
| `traffic_light` | `Traffic light` | `traffic light` | есть | есть |
| `trash_can` | `Waste container` | **нет** | `Trash Can` | есть |
| `bench` | `Bench` | `bench` | `Bench` | есть |
| `sidewalk` | **нет** | **нет** | есть | есть |
| `crosswalk` | **нет** | **нет** | есть (разметка зебры) | есть |

Практический вывод: **семь классов из десяти закрываются полностью
автоматически**, без регистраций и лицензий, и это ровно те семь, которых
не хватает по объёму. Проблемный класс один — `curb`: боксов бордюра нет
ни в одном свободно скачиваемом датасете, он живёт только в
сегментационных (Mapillary Vistas, Cityscapes) и в профильных
сидвок-датасетах, а Vistas у нас уже выбран — значит, размечать руками по
своей съёмке либо запрашивать SideGuide. `sidewalk` и `crosswalk` из модели
предлагается убрать — это площади под ногами, а не препятствия, ёмкость
nano-сети на них тратится впустую.

## Источники и условия

| Источник | Объём | Лицензия | Доступ | Оценка |
| :--- | :--- | :--- | :--- | :--- |
| [Open Images V7](https://storage.googleapis.com/openimages/web/download_v7.html) | 9 M изображений, 600 классов с боксами | изображения CC BY 2.0, разметка CC BY 4.0 | свободный, без аккаунта | **основной источник**, качается по классам |
| [COCO 2017](https://cocodataset.org/) | 118 k train, 80 классов | разметка CC BY 4.0 | свободный, без аккаунта | добавка по `person`/`car`/`bench`, разнообразные ракурсы |
| [Mapillary Vistas](https://www.mapillary.com/dataset/vistas) | 25 k, 124 класса, пиксельная разметка | CC BY-NC-SA | регистрация + принятие research-лицензии | **уже использован** — из него собран текущий датасет (см. выше); остаток около +3 k кадров |
| [Cityscapes](https://www.cityscapes-dataset.com/) | 5 k точных кадров | некоммерческая | регистрация | ракурс с капота, `curb` отдельным классом нет |
| [BDD100K](https://bdd-data.berkeley.edu/) | 100 k, дашкам | BSD-подобная, с соглашением | регистрация | тот же ракурс, что у текущего датасета — усилит уже имеющийся перекос |
| [SideGuide](https://ieeexplore.ieee.org/document/9340734) (IROS 2020) | 350 k с боксами | по запросу | заявка, датасет корейский | **лучшее совпадение по домену** — съёмка тротуара для незрячих; доступ надо запрашивать, выдача не гарантирована |
| [uB-VisioGeoloc](https://pmc.ncbi.nlm.nih.gov/articles/PMC10865199/) | последовательности прогулок пешехода | открытая | свободный | ракурс наш, но детекционной разметки может не быть — надо смотреть |

Регистрацию, заявки и принятие лицензий делает человек: у меня нет права
заводить аккаунты и соглашаться с условиями от вашего имени. Всё, что в
таблице помечено «свободный», скачивается скриптами отсюда без участия
человека.

## Что получилось на практике (сборка 16.08.2026)

31943 кадра против 15918 оригиналов в исходном датасете. Числа ниже —
пересчёт по файлам на диске, а не по сводке сборщика: в сводке был перекос,
см. «грабли» ниже.

| класс | боксов | из них в опасной зоне | было в val исходного |
| :--- | ---: | ---: | ---: |
| pole | 179268 | 4.3% | 20628 (3.2%) |
| car | 72185 | 10.2% | 7853 (9.1%) |
| person | 48442 | 20.5% | 3569 (4.3%) |
| traffic_light | 24780 | 14.2% | 2127 (7.3%) |
| curb | 22786 | — | 2939 |
| sidewalk | 22394 | — | — |
| traffic_sign | 21768 | 26.7% | 2091 (10.1%) |
| bench | 7072 | **73.9%** | **89** (19.1%) |
| trash_can | 6051 | **47.1%** | **418** (26.8%) |
| crosswalk | 5316 | — | — |

Главное здесь не общий объём, а две предпоследние строки: скамейки и урны
были представлены десятками боксов, теперь — тысячами, и большинство из них
крупные объекты вблизи, то есть ровно те, которые система обязана
озвучивать. Выкинуто при сборке: 19536 копий `_aug_*`, 467 битых строк
разметки, 524257 боксов мельче 16 px.

Классов десять, а не восемь. Первая сборка выбрасывала `sidewalk` и
`crosswalk` как площади под ногами, но пешеходный переход нужен в модели,
а выбросить только `sidewalk` нельзя: id зашиты в `threat_logic.cpp`, а
ultralytics требует непрерывную нумерацию с нуля, поэтому дырка в середине
недопустима. Восьмиклассная и десятиклассная сборки по остальным восьми
классам совпадают в точности — проверено пересчётом боксов в обоих
каталогах.

Что осталось кривым: `pole` даёт 44% всех боксов, перекос уменьшился, но не
ушёл. Если после обучения сеть начнёт сыпать столбами — лечится
ограничением числа `pole`-боксов на кадр.

Три грабли, на которые я наступил и которые стоит знать:

* **`--seed-classes` обязателен для редких классов.** Без него fiftyone
  отдаёт кадры с людьми и машинами, а урн и скамеек не приносит. Разметку
  при этом он не обрезает: кадры, отобранные по `Street light`, приезжают
  с размеченными людьми и машинами тоже — проверено, иначе модель выучила
  бы их как фон.
* **`--shuffle` перемешивает только внутри уже скачанного пула.** Проход
  с ним дал 6000 кадров, новых из них ноль. Чтобы получить новые, нужен
  `--max-samples` заведомо больше закэшированного.
* **В `validation` Open Images редких классов почти нет** — `Bench` в 6
  кадрах, `Waste container` в 19. Весь объём в `train`.
* **Сводка сборщика считала боксы до отсева дубликатов.** Проход, принявший
  ноль новых кадров, всё равно добавлял их содержимое в отчёт: числа классов
  в первой публикации этой таблицы были завышены на 3–29% в зависимости от
  класса, при том что на диске лежали правильные файлы. Исправлено в
  `prepare.py`; проверять передачей одного источника дважды — второй проход
  обязан не сдвинуть ни один счётчик.

## Порядок сборки

```bash
pip install fiftyone pyyaml opencv-python

# 1. Open Images: только нужные классы, только нужное количество
python fetch_open.py --source open-images-v7 --split train --max-samples 12000 --out D:/bn_raw/oi_train
python fetch_open.py --source open-images-v7 --split validation --max-samples 2000 --out D:/bn_raw/oi_val

# 2. COCO — добор ракурсов по person/car/bench
python fetch_open.py --source coco-2017 --split train --max-samples 6000 --out D:/bn_raw/coco_train

# 3. Свои кадры с платы — главное лекарство от сдвига домена
python pseudo_label.py --video D:/board_rec/output_video_a.avi --out D:/bn_raw/own --every 15

# 4. Слить, почистить, порезать
python prepare.py --src E:/DATASET --src D:/bn_raw/oi_train --src D:/bn_raw/coco_train \
                  --src D:/bn_raw/own --out D:/bn_dataset --drop sidewalk,crosswalk

# 5. Обучение (GPU)
yolo detect train data=D:/bn_dataset/dataset.yaml model=yolo11n.pt imgsz=640 epochs=150
```

Перед долгой выгрузкой полезно прогнать `--dry-run`: у `fetch_open.py` он
печатает, что будет скачано, у `prepare.py` — всю статистику по классам и
долю ближней зоны, ничего не записывая.

## Чего этот датасет не даст

Открытые данные закрывают объём и баланс классов, но не ракурс. Даже
Open Images и COCO — это фотографии «пейзажного» типа, а не кадр
480-строчной камеры на груди идущего человека с мазнёй от движения и
засветкой. Пока в выборке нет своих кадров, метрики на валидации вырастут
сильнее, чем поведение на улице.

Поэтому порядок вложений такой:

1. **Своя съёмка, 1000–2000 размеченных кадров.** Устройство уже пишет
   видео само; полчаса ходьбы по типовым маршрутам дают исходник. Это даёт
   больше всех остальных пунктов вместе взятых.
2. **Open Images + COCO** — бесплатно, автоматически, поднимают `trash_can`,
   `bench`, `traffic_light`, у которых сейчас мало примеров.
3. **Обучение на 640 вместо 512** и выброс `sidewalk`/`crosswalk`. Скорости
   на это хватает: INT8 на 640 даёт около 17 FPS против нынешних 25 на 512,
   всё ещё вдвое быстрее прежней FP16-версии на 512.
4. **Остаток Mapillary Vistas** (~3 k кадров) — только если `curb` решено
   сохранить, и это последний резерв: основная часть датасета уже оттуда.
   Требует конвертации полигонов в боксы, `prepare.py` их понимает.

Отдельный пункт, который ничего не стоит: **выбросить офлайн-аугментацию**.
19 536 файлов `_aug_*` в train — это копии тех же картинок, они удлиняют
эпоху втрое и не добавляют информации. Аугментацию ultralytics делает на
лету и разнообразнее; отфильтровать копии по маске имени — минус две трети
времени обучения даром.
